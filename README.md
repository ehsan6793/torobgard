# ترب‌گرد — دستیار خرید حضوری تهران

اپ موبایل‌محور فارسی (RTL) برای چالش «دستیار هوشمند خرید حضوری» ترب. کاربر کالا را جستجو می‌کند، فروشندهٔ مناسب را در محدوده/بودجه/زمان مراجعه‌اش پیدا می‌کند، موجودی را پیگیری می‌کند و اگر فروشنده نداشت جایگزین می‌گیرد. هویت بصری (رنگ قرمز، تایپوگرافی) هم‌خانواده با برند ترب طراحی شده است.

## ویژگی‌های کلیدی

- **جستجوی زبان طبیعی فارسی** با FTS5 روی ۲۲۵٬۹۰۳ کالا و ۳۳۱٬۵۰۶ پیشنهاد قیمت از ۶٬۴۷۶ فروشگاه
- **شفافیت کامل قیمت/تاریخ/موجودی** طبق قوانین چالش — هیچ داده‌ای قطعی‌تر از چیزی که واقعاً هست نشان داده نمی‌شود
- **ساعت کاری نسبت به زمان واقعی رسیدن** (نه زمان فعلی)، با محاسبهٔ پیاده‌روی
- **پیگیری موجودی دستی + جایگزین‌یابی خودکار** وقتی فروشنده کالا را ندارد
- **برنامهٔ خرید چندکالایی** با دو گزینهٔ کمترین‌توقف/ارزان‌ترین و مسیر روی نقشه
- **دستیار گفتگویی اختیاری** (LLM با دسترسی محدود به ۴ ابزار) که در نبود کلید یا خطا، به منطق قاعده‌محور برمی‌گردد
- **ریسپانسیو کامل**: موبایل، تبلت، دسکتاپ (نقشه به‌صورت پنل کنار لیست)
- ۱۳ تست خودکار؛ بدون نیاز به build، فقط Vanilla JS

## اجرا

### ویندوز (برای توسعه/دمو محلی)
`1_setup.bat` (نصب) → `2_build_db.bat "مسیر پوشهٔ CSV"` (ساخت دیتابیس، ~۳۰ ثانیه) → `3_run.bat` (اجرا + باز شدن خودکار مرورگر)

### macOS / Linux
```bash
pip install -r requirements.txt
python scripts/build_db.py /path/to/starcoach-dataset-csv data/torob.db   # ~۳۰ ثانیه، ~۲۵۰ مگابایت
python -m uvicorn app.main:app --port 8000                                # http://localhost:8000
pytest -q                                                                 # ۱۳ تست
```

متغیرهای محیطی (اختیاری، برای دستیار هوشمند LLM؛ بدون آن‌ها دستیار قاعده‌محور کار می‌کند):

| متغیر | پیش‌فرض |
|---|---|
| `LLM_API_KEY` | — (خالی = بدون LLM) |
| `LLM_BASE_URL` | `https://api.metisai.ir/openai/v1` (هر API سازگار با OpenAI) |
| `LLM_MODEL` | `gpt-4o` |
| `TOROB_DB` | `data/torob.db` |

## دیپلوی روی لیارا (Docker)

```bash
gzip -k data/torob.db            # data/torob.db.gz (~۱۱۰ مگابایت) داخل ایمیج می‌رود
liara deploy --platform docker --port 8000
liara env set LLM_API_KEY=... -a torobgard   # اختیاری
```
ایمیج هنگام اولین بوت دیتابیس را باز می‌کند (`scripts/entrypoint.sh`) و `/api/health` برای health-check است.

## معماری

```
CSV ترب ──build_db.py──▶ SQLite (FTS5) ──▶ Engine (کش فروشگاه‌ها در حافظه + numpy)
                                           ├─ search / product / shop     جستجو و مقایسهٔ فروشنده
                                           ├─ trip.plan_trip              برنامهٔ خرید چندکالایی
                                           ├─ trip.find_alternatives      جایگزین‌یابی
                                           └─ agent (LLM tool-calling | قاعده‌محور)
FastAPI ──▶ static/ (Vanilla JS، Leaflet، Vazirmatn؛ بدون build)
```

- **دیتا:** ۶٬۴۷۶ فروشگاه، ۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ آفر. جستجوی فارسی با FTS5 + نرمال‌سازی (ی/ک عربی، ارقام، نیم‌فاصله، «مدار بسته/مداربسته»).
- **ساعت کاری:** شیفت‌های ۰۰:۰۰–۰۰:۰۰ در دیتا placeholder هستند و نادیده گرفته می‌شوند؛ وضعیت باز/بسته در **زمان رسیدن** (زمان مراجعه + پیاده‌روی) محاسبه می‌شود.
- **دستیار:** LLM فقط از طریق ابزارها (`search_products`, `get_product_offers`, `plan_trip`, `find_alternatives`) به دیتا دسترسی دارد؛ هیچ قیمت یا فروشگاهی از خودش نمی‌سازد. اگر LLM در دسترس نباشد یا خطا بدهد، تحلیل قاعده‌محور (`nlu.py`) جایگزین می‌شود.

## شفافیت اطلاعات (طبق چالش)

هر پیشنهاد سه چیز را جدا نشان می‌دهد: **قیمت ثبت‌شده**، **تاریخ آخرین تغییر قیمت** (تازه ≤۷ روز، متوسط ≤۳۰، قدیمی) و **موجودی: همیشه «تأییدنشده»**. موارد نامشخص صریح نوشته می‌شوند:

- بدون قیمت / قیمت نامعتبر (<۱۰۰۰ یا >۲×۱۰¹⁰ تومان) → از رتبه‌بندی کنار می‌رود و هشدار دارد.
- قیمت پرت نسبت به بقیهٔ فروشنده‌های همان کالا، و احتمال «قیمت واحدی» (مثلاً قیمت متری) → هشدار.
- ترب‌پی/اقساط: «حضوری تأییدشده» جدا از «اعلام‌شده/نامشخص».
- ساعت کاری ثبت‌نشده → «ساعت کاری ثبت نشده».
- نام و شمارهٔ فروشگاه‌ها در دیتاست نمونه‌اند؛ مکان‌ها واقعی‌اند.

## هوشمندی (پیگیری، جایگزین، شرایط مراجعه)

- **پیگیری موجودی:** پیام آمادهٔ پرسش، وضعیت (نپرسیدم/منتظرم/موجود/ندارد/قیمت فرق دارد)، هشدار بسته‌شدن.
- **جایگزین:** اگر «ندارد» → فروشندهٔ دیگرِ همان کالا + کالاهای مشابه (هم‌دسته، شباهت عنوان/برند، قیمت نزدیک) در محدوده.
- **برنامهٔ خرید:** چند کالا → «کمترین توقف» در برابر «ارزان‌ترین» با توضیح مصالحه (مثلاً ۱ توقف کمتر، ۵۰٪ گران‌تر) و مسیر روی نقشه.
- **شرایط مراجعه:** روز/ساعت دلخواه، ترب‌پی، اقساط، ارسال فوری، گارانتی، تست و تحویل حضوری، بودجه و شعاع.

## محدودیت‌ها

- موجودی و تماس واقعی در دیتا نیست؛ پیگیری دستی است (کاربر می‌پرسد و وضعیت را ثبت می‌کند).
- تصویر محصول و کاشی نقشه از اینترنت لود می‌شوند.
- فاصله خط مستقیم است؛ زمان پیاده‌روی با ضریب ۱٫۳ و سرعت ۴٫۵ کیلومتر بر ساعت تخمین زده می‌شود.
